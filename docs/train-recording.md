# 手持电车采集与站间距离核对

## 先区分不确定度与实测误差

界面的“模型不确定度”是算法输出的误差尺度，不是已经测得的速度差，也不是标定过的置信区间。当前算法在手持模式使用定位速度及其精度，不将手持加速度积分为车速，也没有用经纬度或铁路里程修正实时速度。

`SpeedEstimator.estimate` 的不确定度取协方差速度标准差与保守下限的较大值。该下限不小于最近一次已接收定位的 `speedAccuracy`，还随定位年龄增长。例如 `speedAccuracy = 2.8 m/s` 时，下限就是约 `10.08 km/h`。即使连续 300 秒输入完全正确的匀速观测，该数值仍不会降到下限以下；这不表示已经观察到 10 km/h 的误差。新日志会分别记录这个下限、协方差标准差和定位报告精度，以查明实际行程中的成因。

实时车速会变化。更长时间有助于估计站间平均速度或稳定偏差，但并不自动让“此刻速度”的不确定度持续收敛。不能仅为减小显示值而降低过程噪声或精度下限。

## 手机上的操作

1. 打开应用即开始测速并自动记录。若已停止，点主页面“开始测速并记录”；每次建立独立文件，界面统计与记录从同一边界开始。无需进入历史页面开记录，进入历史也不会重置滤波器或里程。请在进入首段测量区间前开始，让定位有时间完成确认。
2. 主页面只显示测速、里程与记录状态，不提供站名输入或起步、到站等手动标记。测量过程自动采集，无需手动填写。
3. 从前台开始测速后，可以切换应用或锁屏：后台定位已开启，传感器与当前滤波器持续运行。返回只记录前台事件，不主动停止或重置行程。iOS 会显示后台定位指示。系统终止或手动划掉应用仍会中断运行；已落盘文件可恢复，采样间隔和缺口以日志为准。
4. 到终点停稳后点主页面“停止并保存”。写入队列完成、文件同步并关闭后，才出现在文件列表；保存期间禁止再次开始。点“查看本次”直接打开本次详情，顶部“历史”管理全部记录。点文件通过系统分享导出到电脑，也可以在 Finder 的 iPhone 文件共享中取出 Documents 内的 JSONL。再次开始会创建新文件，已有原始数据保持不变。

所有测速都必须记录。创建文件或写入失败会明确提示并停止测速；记录失败时保留可恢复的部分数据，不把它当作成功保存的完整行程。主页面不再提供记录中清零按钮，避免界面统计与原始数据的时间范围脱节。行程名称和备注可在保存后编辑。

### 在应用中管理和分析

历史记录点进去即可查看全过程速度、累计有效距离和模型加速度曲线。拖动曲线或时间滑块，查看该时刻速度、模型不确定度及其构成、a/b/P/NIS、最近定位与运动传感器样本。传感器数据保留自己的测量时间，不把不同频率数据假装为同时测量。曲线按连续可用区间断线；绘图减少点数并保留速度极值，计算与选点使用完整分析采样。

在“距离核对”选择记录起止（旧记录如含事件标记，也可选择标记区间），应用内直接积分并展示米数、覆盖率和最长缺口；填铁路参考距离与来源后，可保存该段对照。只有完整覆盖的区间才给出完整距离误差。名称、备注、参考距离保存在独立 `.notes.json`，不会改写原始 JSONL；导出原始数据时，如需保留人工备注和参考值，也请一并通过 Finder 取出对应 sidecar。

记录列表左划可移入“最近删除”，30 天内可恢复，超过 30 天自动永久删除（以移入时间为准），不提供直接清空原始数据的按钮。剩余空间低于 100 MB 时不开始测速，以免行程中途因磁盘写满丢失结尾。详情页可分享原始 JSONL，也可生成完整分析采样的 CSV。原始高频数据始终保留在 JSONL；CSV 按分析输出时刻对齐最近传感器样本，原始测量时间单独保留。

正常运行无需 Xcode 参数。原有 `--record-sensors` 调试入口仍可用。每次记录文件名含时间与随机标识，独占创建，不追加覆盖旧行程。未正常结束的文件保留在列表，可导出恢复；分析工具会提示结束标记缺失。

记录包含精确经纬度，保存在本机；系统分享的目的地由用户选择。

## 采集范围与单位

| 内容 | 记录信息 |
|---|---|
| Core Location | 定位速度、速度精度、水平精度、经纬度、高度、垂直精度、航向及精度、模拟/外接来源标记、定位墙钟时间与转换后的单调时间 |
| Device Motion | 去重力三轴加速度、重力、角速度、姿态四元数、传感器测量单调时间；参考系 `xArbitraryZVertical` |
| 原始加速度计（诊断开关） | 含重力三轴加速度、测量时间，申请 50 Hz |
| 原始陀螺仪（诊断开关） | 三轴角速度、测量时间，申请 50 Hz |
| 原始磁力计（诊断开关） | 三轴磁场、测量时间，申请 20 Hz |
| 气压计 | 相对高度、压力、测量时间，系统提供的频率 |
| 算法 | 原有约 5 Hz tick、定位及其他模型事件上的速度、状态、来源、观测年龄、不确定度；内部速度/加速度/偏置、协方差、最近的输入结果与定位创新/NIS |
| 其他 | 系统活动分类输入、传感器错误、前后台/reset/结束事件、手动标记、墙钟时间、电量和热状态、设备硬件标识、应用/系统版本、手持或固定模式、传感器可用性与申请采样率 |

原始加速度计/陀螺仪/磁力计默认不记录：融合只使用 Device Motion，这三路与其高度重复，却占日志约三分之二。需要离线诊断时在“行程记录 → 诊断”打开“记录原始 IMU”，下次开始测速生效，`metadata.rawIMURecorded` 标明本次是否包含。Device Motion 各分量写入前量化（加速度/重力/角速度 1e-5，四元数 1e-6，远低于传感器噪声），且在融合前完成，回放仍与实时完全一致。`wallTime`、电量和热状态只写在 tick、定位等主事件上。日志按 64 KB 或 1 秒批量写盘，异常终止最多丢失最后约 1 秒。实测同一段记录由 8.2 MB 降到约 2.6 MB。

手持模式的 Device Motion 在记录期间申请 50 Hz，停止测速时一并停止采集；固定安装模式保留原有 20 Hz 融合输入频率。申请频率不等于实际频率；应使用传感器测量时间检查间隔与延迟。不可用或未授权的传感器没有样本，不能视为读数为零。iOS 模拟器不提供真实手机 IMU/气压数据。

JSONL 的 `receivedAt` 与运动传感器 `timestamp` 以系统启动后的秒数表示；`wallTime` 与 `locationDetails.wallTime` 为 Unix 秒。速度 m/s、距离/高度 m、原始及去重力加速度/重力 g、投影加速度 m/s²、角速度 rad/s、磁场 µT、压力 kPa。转为 SI 加速度需乘 9.80665。姿态是设备相对参考系的四元数 `[x,y,z,w]`，并非车辆前向轴。

`metadata.schemaVersion = 2`；新增字段为可选，现有日志仍可回放。`algorithmID` 标识当前模型版本，应用版本/构建号同时保存。调参时需另行保存源码快照和改动参数；应用版本不等于源码 Git 版本。原始记录保持不变，候选算法另存回放结果。

## 电脑上分析

当前版本不提供手动标记入口。以下按起步、到站生成模板的命令适用于已有相应标记的旧日志；新记录可先核对整段距离，逐站划分需在电脑上结合记录时间与独立行程信息分析。

工具仅依赖 Python 3 标准库。以下命令在仓库根目录运行，示例文件名自行替换。

```sh
# 查看标记、各类样本数量及是否正常结束，并导出诊断曲线数据
python3 tools/analyze_trip.py /path/session.jsonl --csv /path/samples.csv > /path/summary.json

# 按“起步→下一站停稳”生成待填写模板
python3 tools/analyze_trip.py /path/session.jsonl --template > /path/railway.json
```

在 `railway.json` 中填写各段 `distanceMeters` 和 `source`。例如：

```json
[
  {
    "name": "A → B",
    "startMarker": "M002",
    "endMarker": "M003",
    "distanceMeters": 1234,
    "source": "示例：应替换为实际铁路里程来源及区间定义"
  }
]
```

1234 仅为格式示例。标记 ID 必须使用本次记录中的 ID。工具不会联网猜测站名或距离，不允许缺失距离、未知标记、反向时间或重叠测量区间。站间可存在未测量的空档；汇总只包含明确列出的区间，并非默认覆盖整个 A 至 B 行程。

```sh
python3 tools/analyze_trip.py /path/session.jsonl --segments /path/railway.json > /path/comparison.json

# 对同一份输入回放候选算法，再以相同评估时刻核对
swift run speed-replay /path/session.jsonl > /path/replay.jsonl
python3 tools/analyze_trip.py /path/session.jsonl --segments /path/railway.json --replay /path/replay.jsonl > /path/ab.json
```

工具比较原记录输出、原始有效定位速度、可选候选回放。对相邻可用速度作梯形积分，并对标记边界线性插值截取。融合输出间隔超过 1 秒、不可用/reset，或原始定位测量间隔超过 2.5 秒，均不跨越积分，也不补零。它报告已覆盖距离、覆盖率、最长缺口；只有区间完整覆盖才给出完整距离及误差。原始定位按测量时间积分，融合输出按输出单调时间积分；原始定位的边界若缺少前后样本，不作无依据外推。

`distanceErrorMeters` 为估计减参考；`distanceErrorPercent` 为该差除以参考距离。汇总同时给出有符号误差和各段绝对误差之和，避免不同区间正负抵消。各流完整区间可能不同，A/B 必须比较共同完整区间，并检查各自覆盖率，不能仅比各自汇总误差。CSV 内的加速度与偏置是内部模型状态，不是独立实测真值。

## 怎样让这个实验更有说服力

- **距离的边界与精度要说明。** 线路营业里程、站中心里程和实际停车位置之间的距离可能不同。记录来源、是否四舍五入、列车方向和停车位置；条件允许时给出参考距离的误差范围。列车前后位置本身无需再加车长，但两站停车位置相对里程基准的差会影响参考距离。
- **逐站核对，并看整段。** 总距离吻合可能是加速段高估、制动段低估互相抵消。逐站误差、停车残余速度、起步/制动响应和覆盖率一起看；停站不能用算法自己输出的零速当作独立标记。
- **距离验证整体，不确定每秒真值。** 已知 D、T 可核对平均速度 D/T 和速度积分，不能唯一恢复加速/匀速/制动的详细过程。端点停车只约束速度端点；若以站点约束修正了该段结果，同一段距离只能用于说明约束满足，不能再当独立验证。
- **手持分开研究。** 手机去重力加速度仍含手部平移、转动误差、横向转弯和车体振动。不能积分三轴模长获得车速，也不能因为 IMU 安静就判定电车静止。先用日志研究方向、姿态变化与定位速度变化的一致性，再考虑分段方向估计和偏置建模。
- **统计按完整行程分组。** 多次相同区间、往返方向、不同日期分别留档。完整行程分成调参集与保留验证集，连续帧不是独立实验。报告每段误差分布和最差片段；没有独立瞬时速度参考时，不输出瞬时速度 MAE/RMSE 或声称不确定度已完成统计标定。

这一轮建立真实数据的采集和评估能力，不以合成测试替代真实电车标定，也不修改滤波噪声参数。
## 到站提示补充（2026-10-19）

测速记录中，重复的完整运行和停稳过程满足实验门限后，会从顶部询问“可能到站了？”。点“是，到站了”自动添加带停稳时刻的标记；点“不是”记录误报；不操作保留未确认。历史详情可查看反馈，JSONL 保留完整关联，供后续离线调参。第一版需要可靠定位；地下无定位时继续采集，独立记录现场到站时刻供离线核对。规则与限制见[到站推测与反馈](rail-arrival.md)。


## 静止速度显示

系统可能提供位置，却把速度和速度精度标为不可用。新版在静止活动、连续安静运动数据和稳定位置共同支持后显示 0，来源记为 `stationary`，不将负速度当作零。所有证据保留在原始日志，实时与回放使用同一判定。确认需要数秒及足够的位置更新；没有证据时显示“等待速度”，不会假装已经静止。

已确认静止后，手部抖动或转动不会单独撤销零速；维持判定仍需系统静止活动和稳定位置。走动、可信移动速度、位置移动或数据中断会撤销判定，不能无限保留旧零速。首次确认及数据中断后的重新确认仍需足够的安静证据。
